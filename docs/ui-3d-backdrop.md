# หน้า "ทางเข้า": แผงเกลียว DNA 3D (Three.js) + การ์ด monitor

เอกสารนี้บันทึกแนวทางของหน้าทางเข้า (login เริ่ม 2026-11-21, ปรับเป็นแบ่งสองฝั่งและใช้กับ register 2026-11-24) เพื่อใช้ซ้ำ/ต่อยอด
กับหน้าอื่นในอนาคตให้หน้าตาและพฤติกรรมไปทางเดียวกัน อ่านก่อนเพิ่มพื้นหลัง 3D หรือแถบ monitor ให้หน้าใด ๆ

## 1. ใช้ที่ไหน และไม่ใช้ที่ไหน

| ใช้ได้ | ห้ามใช้ |
|---|---|
| หน้า "ทางเข้า" ที่อยู่นอก AppShell: `/login` และ `/register` (ทำแล้วทั้งคู่), หน้าหมดเวลา session ถ้ามีในอนาคต | ทุกหน้าใน AppShell (ตาราง, ฟอร์ม, ข้อมูลผู้ป่วย, คลัง, dashboard, 404) เป็นหน้าทำงานที่ต้องอ่านเร็ว ใช้บนมือถือทั้งเวร พื้นหลังที่ขยับได้กวนสายตาและกินแบต |
| | dialog, หน้า print, หน้า SQL |

หลักคือ: 3D เป็น "จังหวะต้อนรับ" ครั้งเดียวตอนเข้าระบบ ไม่ใช่ของตกแต่งทั่วระบบ ถ้าหน้าไหนผู้ใช้ต้องอยู่นานหรืออ่านข้อมูล ห้ามใส่
(หน้าในแอปใช้ความเรียบ: ปุ่มในแถวตารางสีเรียบ, ตัวกรองไม่ห่อการ์ด, empty state เป็นข้อความ, dashboard เป็นทางลัด ไม่มีตัวเลขแต่ง)

## 2. โครงหน้า (`EntryLayout`)

- จอกว้าง (`lg`+): ซ้าย = แผงเกลียว DNA เต็มความสูง (`bg-sidebar` ของธีม) + ชื่อ **my-his** ตัวใหญ่ + คำโปรย
  "เครื่องมือช่วยงานพยาบาล" ชิดซ้ายล่าง, ขวา = การ์ดฟอร์มกลางแนวตั้ง
- จอเล็ก: แผงเกลียวเป็นแถบบน (~30% ของจอ, ต่ำสุด 160px) ฟอร์มอยู่ล่าง นิ้วโป้งเอื้อมถึงด้วยมือเดียว
- เกลียวอยู่ในแผงของตัวเอง ไม่มีการ์ดบัง ชื่อ/คำโปรยอยู่มุมซ้ายล่างซึ่งเกลียว (พาดซ้ายบนไปขวาล่าง) ไม่ผ่าน จึงอ่านชัดเสมอ
- หัวการ์ดมีแค่ชื่อหน้า (h1) คำโปรยไม่ซ้ำในการ์ด

## 3. แนวคิดของฉาก (DNA helix)

แบบจำลองเกลียวคู่ "ภาพประกอบการแพทย์" ตามภาพอ้างอิงที่ผู้ใช้ให้ (2026-11-24) — วัตถุทึบมีแสงเงา ไม่ใช่จุดอนุภาค:

- **เส้นหลัก (sugar-phosphate backbone):** ท่อแก้วโปร่งแสงสองเส้น (`TubeGeometry` ตามเส้นโค้งเกลียว) รัศมี 0.2R สีตาม `--primary`: แกนทึบเส้นเล็ก (0.42 ของรัศมี) อยู่กลาง + เปลือกหลัง/หน้าโปร่งแสง (opacity ~0.3, `depthWrite:false`) ที่ขอบทึบและสว่างขึ้นตาม fresnel (`glassMaterial` ใน `dnaHelixScene.ts`) เห็นแท่งเบสทะลุผ่านท่อ
- **คู่เบส:** แท่งทรงกระบอกสีตามชนิดเบสจากท่อแต่ละข้างเข้าหากลาง ปลายแท่งเป็นหัวหกเหลี่ยม มีตัวอักษร A/T/C/G แท่งและหัวเป็นแก้วโปร่งแสงแบบเดียวกับท่อ (`glassMaterial`, opacity ~0.4–0.5) มีแกนทึบเล็กข้างในให้เห็นสีและรูปทรง
  ลำดับเบสคงที่ (ไม่สุ่มทุกครั้ง) จับคู่ A–T, C–G ถูกต้อง
- **พันธะไฮโดรเจน:** เส้นประขนานกันกลางคู่เบส A–T 2 เส้น, C–G 3 เส้น
- **สัดส่วน B-DNA:** 10 คู่เบสต่อรอบ, ระยะต่อรอบ 3.4R (≈ 1.7 เท่าของเส้นผ่านศูนย์กลาง), สองสายห่างกันเชิงมุม ~0.8π
  จึงเห็นร่องใหญ่/ร่องเล็กชัด
- **ขนาด/วาง:** แผงแนวตั้ง (ซ้ายของจอกว้าง) R = 20% ของความกว้างแผง พาดเส้นทแยงซ้ายบน→ขวาล่าง เห็นราว 2–3 รอบ
  (มุมซ้ายล่างที่มีชื่อ my-his ว่าง); แผงแนวนอน (แถบบนมือถือ) R = 15% ของความสูง เกือบนอน (-0.2 rad) อยู่ครึ่งบนของแถบ
  ไม่ทับชื่อ/คำโปรย
- ตัวอักษรบนหัวเบสเป็น sprite ที่ถูกยกมาหน้าหัวไปทางกล้องทุกเฟรมและทดสอบความลึกตามปกติ (ท่อที่อยู่หน้าบังตัวอักษรได้ถูกต้อง)
  แสดงเฉพาะครึ่งหน้าของเกลียว
- **การตอบสนอง** (พิกัดเมาส์เทียบกับกรอบ canvas ของแผง ไม่ใช่ทั้งหน้าต่าง):
  | การกระทำ | ผล |
  |---|---|
  | อยู่นิ่ง | หมุนรอบแกนตัวเองช้า ๆ 0.12 rad/s |
  | ขยับเมาส์/ลากนิ้วในแผง | ทั้งเกลียวเอียงตามตำแหน่ง (damping แบบ exponential) |
  | ชี้ที่คู่เบส | คู่นั้นสว่างขึ้น (ผสมขาว 50%) ตัวอักษรใหญ่ขึ้น (raycast กับแท่ง/หัวเบส) |
  | คลิก/แตะในแผง | หมุนเร็วขึ้นชั่วคราวแล้วค่อย ๆ ช้าลง (impulse สะสมได้ถึงเพดาน) |
  | เมาส์ออกนอกแผง/ยกนิ้ว | ค่อย ๆ กลับสู่สภาพปกติ |

## 4. สีและธีม

สีอ่านจาก CSS variable ของธีม **ณ เวลารัน** ไม่ hardcode เปลี่ยนสีใน `src/index.css` แล้วฉากเปลี่ยนตามเอง

| บทบาท | token ธีมมืด (dark, ocean) | token ธีมสว่าง (light) |
|---|---|---|
| เส้นหลักเส้นแรก (ต้นทางของการไล่สี) | `--primary` | `--primary` |
| เส้นหลักเส้นที่สอง/ขอบแก้วเรือง/แสงขอบหลัง (ปลายทางของการไล่สี) | token ใน `--chart-1..5`, `--accent` ที่ hue ห่างจาก primary มากที่สุด (`pickPartner`) | เหมือนกัน |
| เบส A (ฟ้า) | `--chart-2` | `--chart-2` |
| เบส T (เหลือง/ส้ม) | `--warning-ink` | `--warning` |
| เบส C (แดง) | `--danger-ink` | `--danger` |
| เบส G (เขียว) | `--success-ink` | `--success` |
| พันธะไฮโดรเจน | `--foreground` | `--muted-foreground` |
| ตัดสินว่ามืด/สว่าง | `--background` luminance < 0.5 = มืด | |

**ความสด (`vivid` ใน `MedicalBackdrop.tsx`):** สีที่อ่านจาก token ถูกดันให้อิ่มสีอย่างน้อย 0.75 และจำกัดความสว่าง (ธีมมืด L 0.58–0.68, ธีมสว่าง L 0.36–0.46) ให้สดและตัดกับพื้น ไม่หม่นเป็นพาสเทล
**ลักษณะ:** เส้นหลักสองเส้นไล่สี primary → สีปลายทางตามความยาว (เส้นที่สองไล่ย้อน เป็นสีคู่ตรงข้ามกันทุกตำแหน่ง) ขอบแก้วเรืองสีปลายทาง และวัสดุมีแสงในตัว (`uGlow`) ให้สีไม่ดับตามมุมแสง

ธีมมืดใช้ `*-ink` (สว่าง อ่านชัดบนพื้นมืด) ธีมสว่างใช้สีพื้นปุ่ม (เข้มกว่า เห็นชัดบนพื้นขาว) — ไม่มีสี hardcode นอกจากสีสำรอง
ตอนอ่าน token ไม่ได้

- **color space:** `readThemeColor()` (`src/lib/cssColor.ts`) คืน sRGB 0–1 แล้วใส่ `THREE.Color.setRGB(r, g, b, SRGBColorSpace)`
  ให้ three แปลงเป็น linear สำหรับคำนวณแสงเอง วัตถุมีแสงเงา สีบนจอจึงสว่าง/มืดตามมุมแสง ไม่ตรงค่า token เป๊ะทุกจุด
- แสง: HemisphereLight (พื้นสะท้อนเข้มในธีมมืด/เทาอ่อนในธีมสว่าง) + แสงหลักซ้ายบนหน้า + แสงขอบสี `--primary` จากด้านหลัง
- `readThemeColor` ให้เบราว์เซอร์ parse สีเอง (วาด 1px ลง canvas 2D แล้วอ่านกลับ) ใช้ได้กับ oklch/hex/ทุกรูปแบบ parse ไม่ได้คืน
  `null` (มี sentinel กันกรณี canvas เงียบแล้วคงค่าเดิม) ผู้เรียกต้องมีสีสำรอง
- สลับธีมระหว่างเปิดหน้า: `MutationObserver` ดู `class` บน `<html>` แทน theme state ของ React (effect ของลูกรันก่อน effect ของ
  `ThemeProvider` ที่สลับ class อ่านตาม state จะได้สีธีมเก่า)

## 5. โครงโค้ด

```
frontend/src/
├─ lib/cssColor.ts                       readThemeColor(varName) → sRGB | null (ใช้ได้กับงานวาดเองทุกแบบ)
├─ components/layout/BrandMark.tsx       สัญลักษณ์หัวใจในกล่อง primary (sm = sidebar, md = แถบ monitor) ใช้ที่เดียวนี้ทั้งแอป
└─ components/backdrop/
   ├─ EntryLayout.tsx                    โครงหน้าทางเข้าสองฝั่ง (แผงเกลียว + ชื่อ / เนื้อหา)
   ├─ VitalsBand.tsx                     หัวการ์ดแบบจอ monitor (ข้อ 8)
   ├─ MedicalBackdrop.tsx                component React: canvas + lifecycle + event + fallback (ไม่ import three ตรง ๆ)
   └─ dnaHelixScene.ts                   Three.js ล้วน: createDnaHelixScene(canvas, options) → HelixScene
```

**การใช้ในหน้า** (ดู `features/auth/LoginPage.tsx`, `features/registration/RegisterPage.tsx`):

```tsx
<EntryLayout>
  <Card className="w-full max-w-sm gap-5 pt-0">
    <VitalsBand mode={locked ? 'locked' : isSubmitting ? 'busy' : 'rest'} alertKey={alertKey} />
    <CardHeader><CardTitle className="text-lg font-semibold"><h1>ชื่อหน้า</h1></CardTitle></CardHeader>
    <CardContent>…ฟอร์ม (ช่องกรอก/ปุ่ม h-10)…</CardContent>
  </Card>
</EntryLayout>
```

- ช่องกรอกและปุ่มบนหน้าทางเข้าสูง 40px (`h-10`) เพราะเปิดบนมือถือมือเดียวเป็นหลัก (ค่ามาตรฐานของระบบ 32px)
- **การ์ดทึบ (`bg-card`) ห้ามใส่ `backdrop-blur`/พื้นโปร่ง**: เคยลองตอนเกลียวอยู่หลังการ์ด backdrop-filter ทับ canvas ที่วาดทุกเฟรม
  ต้อง blur ใหม่ทุกเฟรม (แพงบนมือถือ) และมองไม่เห็นเกลียวผ่านการ์ดอยู่ดี ตอนนี้เกลียวอยู่แผงของตัวเองแล้วยิ่งไม่จำเป็น
- **dev เท่านั้น:** Fast Refresh (แก้ `dnaHelixScene.ts`/`MedicalBackdrop.tsx` ระหว่าง `bun run dev`) รัน effect ซ้ำบน canvas
  ตัวเดิม ซึ่ง `dispose()` สั่ง `forceContextLoss()` ไปแล้ว เกลียวอาจว่าง/หายจนกว่าจะรีโหลดหน้า ไม่ใช่บั๊กของ production
  (production mount ใหม่ได้ canvas ใหม่ทุกครั้ง)

**API ของฉาก** (`HelixScene`): `setPalette`, `setPointer(ndcX, ndcY)`, `clearPointer`, `impulse`, `resize(w, h)`,
`setReducedMotion`, `setActive` (false = หยุด rAF), `dispose`

**เพิ่มฉากใหม่**: สร้าง `components/backdrop/<ชื่อ>Scene.ts` ที่ export ฟังก์ชัน `create…Scene(canvas, { reducedMotion, palette })`
คืน interface เดียวกัน แล้วให้ `MedicalBackdrop` รับ prop เลือกฉาก (ใช้ `import()` แยกต่อฉาก ทุกฉากต้องอยู่ใน chunk ของตัวเอง)
อย่าเพิ่มฉากที่สองถ้ายังไม่มีหน้าที่ต้องใช้จริง

## 6. งบประสิทธิภาพ

- `three` โหลดด้วย dynamic import ตอน mount เท่านั้น → chunk `dnaHelixScene-*.js` (~534 kB / 133 kB gzip) ไม่อยู่ใน
  `index-*.js` ตรวจหลัง build ทุกครั้งที่แก้ (`grep -c forceContextLoss dist/assets/index-*.js` ต้องได้ 0)
  **ห้าม import อะไรจาก `three` หรือ `dnaHelixScene.ts` แบบ static** นอกจาก `import type`
- geometry สร้างตามขนาดแผง (ท่อ 2 เส้น + `InstancedMesh` 3 ชุด: แท่ง, หัว, ขีดพันธะ) สร้างใหม่เฉพาะตอน resize ที่รัศมีเปลี่ยนเกิน 2%
  ต่อเฟรมแค่หมุนกลุ่ม + เอียงตามเมาส์ + จัดตำแหน่งตัวอักษร (~50–100 sprite) + raycast เฉพาะเมื่อเมาส์ขยับ
- `antialias: true` (วัตถุทึบต้องมีขอบเรียบ), `powerPreference: 'low-power'`, pixel ratio ≤ 2
- Chrome แบบ headless (SwiftShader, เรนเดอร์ด้วย CPU) ใช้เวลาคอมไพล์ shader ของวัสดุมีแสงหลายวินาที เกลียวจึงจางเข้าช้าตอนเทส
  ภาพหน้าจออัตโนมัติ (รอ ~10 วินาที) — บนเครื่องจริงที่มี GPU เร็วกว่านั้นมาก
- หยุด rAF เมื่อแท็บซ่อน (`visibilitychange`); context หาย (`webglcontextlost`) → หยุดวาด
- ออกจากหน้า → `dispose()` ปล่อย geometry/material/renderer แล้ว `forceContextLoss()` (กัน WebGL context สะสมจากการเข้า-ออก
  หน้าซ้ำ เบราว์เซอร์จำกัดจำนวน context ต่อหน้า)
- ไม่ต้องแก้ CSP (`frontend/Caddyfile`): chunk โหลดจาก `'self'`, Three.js ไม่ใช้ eval/worker

## 7. Accessibility และ fallback

- canvas เป็น `aria-hidden` และ `pointer-events-none` ฟังเมาส์ที่ `window` (ตัดสินด้วยกรอบของ canvas) ฟอร์ม/Turnstile คลิกได้ตามปกติ
- `prefers-reduced-motion: reduce` → วาดเฟรมเดียวแบบนิ่ง: ไม่หมุน ไม่เอียง ไม่คลายเกลียว ไม่ส่าย ไม่ตอบสนองเมาส์
  (วาดใหม่เฉพาะตอน resize/เปลี่ยนธีม) และฟังการเปลี่ยน setting ระหว่างเปิดหน้า
- canvas เริ่มที่ opacity 0 แล้วจางเข้า 700ms เมื่อฉากพร้อม ระหว่างโหลดเห็นแผงพื้นเรียบ ไม่มีกระพริบ
- ไม่มี WebGL / สร้าง renderer ไม่ได้ / chunk โหลดไม่สำเร็จ → ถอด canvas ออก เหลือแผงพื้นเรียบ `bg-sidebar` หน้าใช้งานได้ปกติ

## 8. การ์ดแบบจอ monitor (`components/backdrop/VitalsBand.tsx`)

**สถานะการใช้งาน:** หน้า login เอา `VitalsBand` ออกแล้ว (ผู้ใช้สั่ง 2026-11-24) ตอนนี้ใช้เฉพาะหน้าลงทะเบียน (`RegisterPage`) ส่วนข้อ 5 ด้านล่างที่ยกตัวอย่าง login ให้ใช้เป็นแนวทางเมื่อกลับมาใช้ในหน้าอื่น
หัวการ์ดเป็นแถบ "จอ monitor": `BrandMark` (หัวใจเต้นแบบ lub-dub) + เส้น ECG ที่เลื่อนไปทางซ้าย บนพื้นกระดาษกราฟ ECG
(`bg-ecg-grid` ใน `index.css`: ช่อง 25px/5px, พื้น `--muted` เส้นกริด `--foreground` จาง ๆ สีกลางของธีม ไม่อมสี primary)
เป็น `aria-hidden` แต่จังหวะ/สีบอกสถานะฟอร์ม (ผู้ใช้ขอให้ช้าลง 2026-11-24 จังหวะจึงไม่ใช่อัตราการเต้นจริง):

| สถานะ | จังหวะ (`--beat`) | สีเส้น |
|---|---|---|
| `rest` ปกติ | 1.5 วินาที | `--primary` |
| `busy` กำลังส่งฟอร์ม | 0.75 วินาที | `--primary` |
| `locked` ถูกล็อก (login) | 2.6 วินาที | `--muted-foreground` |
| `alertKey` เปลี่ยน (ส่งไม่สำเร็จ) | ไม่เปลี่ยน | กะพริบ `--destructive` 1.6 วินาที (Web Animations API) |

- **ห้ามใช้เส้นแบน (flatline)** สื่อสถานะใด ๆ ในงานพยาบาลมีความหมายเดียว

- reduced motion: เส้นนิ่ง หัวใจไม่เต้น แต่สีกะพริบยังอยู่ (บอกสถานะ ไม่ใช่การเคลื่อนที่)
